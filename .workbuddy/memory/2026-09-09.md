# 2026-09-09

## USART1 改到 PB6/PB7（已落地）

结论：**骄阳板 USART1 = PB6(TX) / PB7(RX)**，AF7 复用，F4 不需要 AFIO REMAP（F1 才有 AFIO->MAPR）。
依据：实战指南 md 代码清单 20-1b（标题写明骄阳）、20-4 注释、§19.5.2.2.1 正文，三处一致；规格书图 2.4-28 原理图 OCR 网络标号也是 PB6/PB7。
（md 1645 行说骄阳=PA9/PA10 是笔误，与 1741 行自相矛盾。）

### 已修改

- `DeltaRobot_F407.ioc`：Mcu.Pin8/9 → PB6/PB7；新增 `PB6.Signal=USART1_TX`、`PB7.Signal=USART1_RX`；删除 PA9/PA10 块
- `Core/Src/usart.c`：MspInit/MspDeInit 改 GPIOB + PIN_6|PIN_7
- `Core/Src/main.c`：① 删掉 HAL_Init() 之前的 printf（huart1 未初始化 → HAL_BUSY 静默失败），移到 USER CODE 2；② 新增 `HAL_UART_ErrorCallback` 重启接收
- `Core/Src/stm32f4xx_it.c`：去掉重复的 USER CODE BEGIN 1/END 1 标记
- `CLAUDE.md`：USART1 引脚改 PB6/PB7、注明 J6/J7 跳线帽必须装、更正"板载 ST-Link"（骄阳板没有，只有 1×5P XH2.54 SWD 座）、两个 Type-C 是 USB Device(PA11/PA12) 与 USB 转串口(CH340)
- `Docs/usart1_diagnostic.md`：追加第六章"已实施的修改"

### 踩坑

- **本环境 Read 工具读不了图片**（返回 "current model does not support images"）。需要读原理图必须走 OCR：`rapidocr-onnxruntime` 可用；`res/` 下 PDF 原件已被替换为 MinerU 输出文件夹，只剩图片。
- **main.c / stm32f4xx_it.c 是 GBK 编码**（其余 Core 文件是 UTF-8）。改这两个文件必须用 GBK 字节级写入，否则 Keil 里中文变乱码。
- Python 读写时 `io.open(...,newline='')` 会丢 CRLF，改完要检查并把 LF 还原成 CRLF（工程其余文件都是 CRLF）。
- stm32f4xx_it.c 里"乱码"的中文注释其实是正确的 GBK，只是 Read 工具按 UTF-8 解码显示错了，不要当成 bug 去"修复"。

### 第二轮：仍然无输出 → 改为"心跳 + 双引脚轮流"诊断

新增怀疑点（很可能就是它）：**开机信息只发一次**，用户先上电后开助手就永远看不到。

- `main.c` 主循环改为每秒打印心跳，并交替把 USART1 切到 PB6/PB7 与 PA9/PA10，各带标签 `[PB6/PB7] alive N` / `[PA9/PA10] alive N`；新增 `static void USART1_UsePins(GPIO_TypeDef*, uint16_t)`（写在 USER CODE 4，原型在 USER CODE PFP）。
- 规格书确认：晶振 25MHz；§2.5.1② 要求 J6/J7 跳帽连接 USART1 与 CH340；§2.4.30 明确该口**不具备串口 ISP 下载功能**，且拔掉跳帽可当独立 USB 转串口模块用（即默认应装着）。

### 事故：main.c 被写空并已重建

- 原因：用 `io.open(...,'w',encoding='gbk')` 写含 U+FFFD 的字符串时抛 `UnicodeEncodeError`，文件已被截断为 0 字节。工程**没有 git**，无备份。
- 已按之前的完整读取内容重建 `main.c`（GBK + CRLF），已核对无 U+FFFD、可正常 GBK 解码。备份：`Docs/backup/main.c.gbk.bak`。
- 教训（务必遵守）：改 `main.c` / `stm32f4xx_it.c` 这类 GBK 文件时，**先备份**；写之前先 `decode(...,errors='replace')` 检查是否残留 U+FFFD；或干脆先用 Write 工具写 UTF-8，再用 Python 转 GBK（字符集校验后再落盘）。
- 建议给用户：这个工程应该 `git init` 一次。

### 第三轮：USART1 已通（结论定案）

用户实测：LED 闪烁 / COM3(CH340) 已识别 / J6-J7 跳线帽一直装着 / 主动打印没收到 / **但助手发字符能收到回显**。

**回显能通 = RX 与 TX 双向都通**，且 PA9/PA10 时期一次都收不到、改 PB6/PB7 后回显出现 → **PB6=TX、PB7=RX 实测确认**。
没收到主动打印是因为下载的是"开机只发一次"的旧固件（先上电后开助手就错过了），不是硬件问题。

最终 main.c（已落盘，GBK+CRLF）：固定 PB6/PB7、删掉双引脚轮流诊断、主循环 1s 心跳 `printf("[PB6/PB7] alive %lu\r\n", aliveCnt++)`、保留 HAL_UART_ErrorCallback。
判定新旧固件的方法：**LED 1 秒一闪 = 新固件**（旧的是 0.5 秒）。

### 工程约定（重要）

- **`main.c` / `stm32f4xx_it.c` 是 GBK 编码**，其余 Core 文件 UTF-8。Write 工具会沿用已有文件的编码（文件非空时会写 GBK），所以直接 Write 即可，无需再手工转码；但用完必须 `decode('gbk')` 校验无 U+FFFD。
- 改任何源码前先 `cp` 备份到 `Docs/backup/`。
- 工程**没有 git**，强烈建议 `git init`。
